# 症状对照表(抓包 ↔ 设备侧)

排查时先抓包(Step 2),用 `pcap_summary.sh` 得到指标,再按下表定位方向,最后用 SSH/Telnet 到设备侧核实(Step 4)。

| 抓包现象 | 常见原因 | 设备侧核查动作 |
|---|---|---|
| TCP 大量重传 / 乱序 | 链路质量差、拥塞、双工不匹配 | `show interface` 看 CRC/错误计数、双工模式 |
| SYN 发出无 ACK(SYN 无响应) | 对端未监听、防火墙拦截、回程路由缺失 | 检查对端服务端口、ACL/firewall 规则、路由表 |
| 大量 TCP RST | 对端主动拒绝、中间设备注入 RST、会话超时 | 查设备会话表/连接限制、检查中间安全设备 |
| DNS NXDOMAIN / 无响应 | 域名解析失败、DNS 服务器不可达 | 在设备侧 `nslookup`/`dig`,检查 DNS 配置与可达性 |
| DHCP 无 Offer | DHCP 地址池耗尽、中继缺失、VLAN 不通 | 查地址池使用率、中继配置、VLAN 成员 |
| TLS 告警 / 握手中断 | 证书过期、协议版本不匹配、中间设备阻断 | 核对证书有效期、客户端与服务端加密套件 |
| ARP 请求风暴 | 环路、广播域过大、IP 冲突 | 查 MAC 表震荡、STP 状态、冲突 IP |
| ICMP 不可达(管理禁止/端口不可达) | 路由黑洞、ACL 拒绝、端口关闭 | 沿路径逐跳 `traceroute`,逐台核对 ACL |
| 带宽跑满、延迟升高 | 大流量下载/备份、P2P | 抓包看 Top 会话,设备侧看接口流量与 QoS |
| 无线客户端频繁掉线 | 信道干扰、信号弱、漫游配置 | 查 AP 客户端数、信号强度、信道占用 |

## 处置建议模板

写成四段式,便于复核:

1. **现象**:客户端访问 X 服务失败,抓包见 SYN 重传 12 次
2. **证据**:cap.pcap 第 88/124/160 包;设备侧 `show interface Gi0/1` CRC 计数 增加 340
3. **根因**:网线/光模块故障导致链路误码
4. **处置**:更换线缆/模块,复测 CRC 不再增长,业务恢复

## 安全与合规

- Telnet 明文传输,存在账号泄露风险:**仅限受控实验环境**,生产环境使用 SSH
- 抓包可能包含敏感数据:抓包文件按公司数据规范存放,排查结束及时清理
- 对第三方网络抓包前,须获得书面授权
