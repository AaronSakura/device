# 答辩演示脚本(配合 10 分钟展示)

**演示前 5 分钟准备**

```bash
sudo apt install wireshark tshark    # 只需一次
bash demo/run_demo.sh                # 先试跑一遍,确认全流程通
```

终端字号调大、背景调深,保证投影清晰。

## 演示流程与话术

| 时间 | 操作 | 话术要点 |
|---|---|---|
| 0′ | 展示技能结构 `ls skills/wireshark-ssh-telnet` | "这个技能把抓包分析和设备调试串成闭环,分 5 步:依赖→假设→抓包→分析→核查" |
| 1′ | `bash demo/run_demo.sh` 开始执行 | "现在我在本地模拟一次故障排查:先产生正常与异常流量" |
| 2′30″ | 脚本进入抓包步骤 | "抓包我会先明确假设和过滤器,不盲抓;这里抓回环接口 8 秒" |
| 4′ | 展示分析输出 | "摘要里能看到协议分层、重传、DNS 失败、RST 等指标,对照症状表定位方向" |
| 6′ | 展示设备核查输出 | "再通过 SSH/Telnet 到设备侧核对接口计数和日志,形成证据闭环" |
| 7′30″ | 展示证据目录 `ls -la /tmp/net_demo_*` | "pcap + 摘要 + 设备输出三件套,别人可以复核我的结论" |
| 8′30″ | 打开 Gitee/GitCode 开源页 | "这个技能我开源发布,别人也能复用" |

## 现场风险预案

- **GitHub/外网不通**:演示脚本全程只走本地回环,不依赖外网;开源页提前截图或另存本地
- **没装 tshark**:脚本自动跳过抓包并提示安装;可用提前录好的抓包环节录屏补位
- **端口被占用**(18080):改 `run_demo.sh` 里的端口号即可

## 结论模板(现场收尾用)

> 现象:访问 18081 端口被拒绝;证据:`cap.pcap` 中 RST 报文,`device_22.txt` 显示端口不可达;
> 根因:目标服务未监听;处置:确认服务状态并启动。
